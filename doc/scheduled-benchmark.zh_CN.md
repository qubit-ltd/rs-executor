# 定时执行器基准

`scheduled_executor_bench` 是轻量且不引入额外依赖的基准程序。它补充历史配对实验 [performance-exe-003.md](performance-exe-003.md)，不替代或改写其中的结论。每类负载先运行一轮预热，预热数据不进入结果。每个测量轮次使用新的调度服务；服务构造和正常关闭不计入负载计时。

## 负载与指标

| 负载 | 每个测量轮次的工作 | 输出指标 |
| --- | --- | --- |
| `sequential` | 逐个提交并观察 10,000 个零延迟任务。 | 轮次总耗时（`ns`），从提交到观察结果的任务延迟 p50/p95（`ns`）。 |
| `batch` | 提交 10,000 个零延迟任务，再观察结果。 | 轮次总耗时（`ns`），从提交到观察结果的延迟 p50/p95（`ns`）。这不代表任务启动或完成延迟。 |
| `future_deadline` | 串行提交 64 个独立探针，每个截止时间为提交后 5 ms。 | 闭包启动晚于截止时间的延迟 p50/p95（`ns`）；时间在任务闭包内通过 `Instant::now()` 记录。 |
| `earlier_deadline` | 每个探针先入队一个 60 s 后触发的 sentinel，再提交一个 5 ms 后触发的探针。探针完成后取消 sentinel。 | 闭包启动延迟 p50/p95（`ns`）。sentinel 必须成功取消，最终结果必须为 `Cancelled`。 |
| `cancel_far_future` | 入队 1,000 个截止时间为 60 s 后的任务，再取消全部任务。建队不计入取消计时。 | 取消阶段总耗时和单任务平均耗时（`ns`）；峰值队列数与取消后的队列数（`count`）；捕获值析构数（`count`）。 |

定时负载使用有界启动通知；探针在 5 秒内未启动即报告失败。该超时用于发现故障，不是性能门槛。每个样本都会检查任务闭包是否在截止时间之后启动。更早截止时间负载测量的是较早任务插入、同时队列中已有较晚任务的情形。公共接口无法证明 worker 当时已经阻塞等待 sentinel，因此该负载不宣称确定覆盖内部 wait 中断交错；这一竞态由调度器单元测试覆盖。

每轮内的 p50/p95 使用 nearest-rank 索引计算。跨轮汇总使用各轮统计值的中位数。轮数为偶数时，中位数取中间两个纳秒数值的算术平均并向下取整。原有 `sequential` 与 `batch` 样本字段布局保持不变；仅偶数轮的汇总语义改变，从选择较大的中间值改为中间两值平均。

`queued_count` 和捕获值析构数是逻辑资源生命周期指标，不是分配次数、常驻内存或线程 join 的测量结果。本基准不安装全局分配器，也不采样进程内存。

## 配置与复现

默认值为 15 个测量轮次、每类负载预热一次、每轮定时样本 64 个、现有即时负载每轮 10,000 个任务、远期取消任务 1,000 个、探针截止时间 5 ms、sentinel 截止时间 60 s。轮数和定时样本数都应为正整数：

```bash
SCHEDULED_BENCH_ROUNDS=15 SCHEDULED_BENCH_TIMER_SAMPLES=64 \
  timeout 600s cargo bench --bench scheduled_executor_bench
```

`SCHEDULED_BENCH_TIMER_SAMPLES=0` 或非整数会输出明确诊断并失败。基准以逐行 CSV 风格文本输出。`*_ns` 字段的单位为纳秒，`*_unit=count` 字段表示数量。请将每次运行的 stdout 与 stderr 原样保存，并记录源码版本、锁文件摘要、操作系统、CPU、Rust 工具链、负载参数及竞争负载。基线和候选应在同一机器、相同参数下交替运行。不要把机器相关的计时噪声解释为通用的通过或失败门槛。
